# PRD-07: 数据库对象管理

## 1. 功能概述

数据库对象管理模块覆盖视图（View）、存储过程/函数（Routine）、触发器（Trigger）、事件调度器（Event）的创建与编辑，以及创建数据库（Create Database）和数据库对象选择器（Select DB Object）对话框。所有编辑器以标签页形式嵌入主界面右侧编辑区域，共享统一的保存/丢弃/帮助按钮布局。

## 4. 功能详细说明

### 4.1 视图编辑器 (TfrmView)

#### 4.1.1 视图名称
- **控件**: `editName` (TEdit), MaxLength = NAME_LEN
- 新建模式: 空文本
- 编辑模式: 显示当前视图名称
- 支持重命名: 编辑模式下修改名称会在保存时追加 `RENAME TABLE old TO new` 语句

#### 4.1.2 算法 (Algorithm)
- **控件**: `rgAlgorithm` (TRadioGroup)
- 选项: UNDEFINED / MERGE / TEMPTABLE
- 默认: UNDEFINED (ItemIndex=0)
- **仅 MySQL 生效**: 非 MySQL 数据库时禁用

#### 4.1.3 Definer
- **控件**: `comboDefiner` (TComboBox)
- TextHint 显示当前用户 `user@host`
- 下拉时从 `mysql.user` 加载所有用户主机组合
- 留空表示使用 CURRENT_USER
- 仅 MySQL 启用

#### 4.1.4 SQL Security
- **控件**: `comboSecurity` (TComboBox)
- 选项: Definer / Invoker
- 仅 MySQL 启用

#### 4.1.5 Check Option
- **控件**: `rgCheck` (TRadioGroup)
- 选项: NONE / CASCADED / LOCAL
- 生成 `WITH ... CHECK OPTION` 子句
- 仅 MySQL 启用

#### 4.1.6 SQL Body
- **控件**: `SynMemoBody` (TSynMemo)
- SQL 语法高亮 + 代码补全
- 新建时预填 `SELECT `
- 编辑时通过 `ParseViewStructure` 解析 CREATE VIEW 语句提取 SELECT 部分

#### 4.1.7 CREATE Code 预览
- **控件**: `SynMemoCreateCode` (TSynMemo), 只读
- 实时生成 CREATE/ALTER VIEW 语句
- 任何修改触发 `ComposeCreateStatement` 重新生成

#### 4.1.8 权限控制
- 若用户无 `SHOW CREATE VIEW` 权限，`SelectCode` 为空
- 此时禁用整个编辑器，显示红色提示标签 `lblDisabledWhy`

#### 4.1.9 保存逻辑 (ApplyModifications)
1. 调用 `ComposeCreateStatement` 生成 SQLBatch
2. 新建: `CREATE [ALGORITHM=...] [DEFINER=...] [SQL SECURITY ...] VIEW name AS select_body [WITH ... CHECK OPTION]`
3. 编辑: `ALTER VIEW ...`（同上语法）
4. 重命名: 追加 `RENAME TABLE old_name TO new_name`
5. 执行所有语句，刷新对象树和编辑标签

### 4.2 存储过程/函数编辑器 (TfrmRoutineEditor)

#### 4.2.1 名称与类型
- **editName**: 例程名称, MaxLength = NAME_LEN
- **comboType**: Procedure（不返回结果）/ Function（返回结果）
- 切换类型时:
  - Function 启用 Returns 字段
  - Function 参数方向固定为 IN（不可编辑）
  - Procedure 参数支持 IN/OUT/INOUT

#### 4.2.2 参数管理
- **控件**: `listParameters` (TVirtualStringTree)
- 4 列: # / Name / Datatype / Context
- 工具栏按钮: 添加 / 删除 / 清空 / 上移 / 下移
- **添加参数**: 自动命名 Param1/Param2..., 默认类型 INT, 默认方向 IN
- **行内编辑**:
  - Name 列: 文本编辑
  - Datatype 列: 枚举编辑器，列出所有数据库数据类型（含长度），允许自定义输入
  - Context 列: 枚举编辑器 IN/OUT/INOUT（Function 时禁止编辑）
- **拖拽**: 支持将参数拖入 SQL Body，自动插入参数名
- **图标**: Context 列显示箭头图标表示方向（IN→120, OUT→121, INOUT→122）

#### 4.2.3 选项
- **DataAccess**: Contains SQL / No SQL / Reads SQL data / Modifies SQL data
- **Security**: Definer / Invoker
- **Deterministic**: 复选框，非确定时生成 `NOT DETERMINISTIC`
- **Comment**: 文本输入
- **Definer**: 同视图

#### 4.2.4 Returns
- 仅 Function 时启用
- 下拉列出所有数据类型，支持自定义输入

#### 4.2.5 保存逻辑 (ApplyModifications)
由于 MySQL 不支持 ALTER PROCEDURE/FUNCTION 修改参数，采用临时例程策略:
1. 生成唯一临时名 `HeidiSQL_temproutine_N`
2. 用临时名创建例程（语法检查）
3. 删除临时例程
4. 删除原例程
5. 若目标名已存在（重命名冲突），确认后删除目标例程
6. 用最终名称创建例程
7. 刷新对象树

#### 4.2.6 CREATE 语句生成
```sql
CREATE [DEFINER=...] PROCEDURE|FUNCTION name(
    IN param1 INT,
    OUT param2 VARCHAR(50)
)
RETURNS INT              -- 仅 Function
LANGUAGE SQL
[NOT] DETERMINISTIC
CONTAINS SQL
SQL SECURITY DEFINER
COMMENT 'comment text'
BEGIN ... END
```

#### 4.2.7 运行按钮
- `btnRunProc`: 运行存储过程（仅 Procedure 时显示）
- 关联 MainForm.actRunRoutines

### 4.3 触发器编辑器 (TfrmTriggerEditor)

#### 4.3.1 触发器名称
- 新建时自动生成: `{table}_{timing}_{event}`（如 `users_before_insert`）
- 仅当用户未手动修改名称时才自动生成（`editName.Modified` 标志）

#### 4.3.2 Timing（触发时机）
- MySQL/PostgreSQL: BEFORE / AFTER
- SQLite: BEFORE / AFTER / INSTEAD OF

#### 4.3.3 Event（触发事件）
- INSERT / UPDATE / DELETE

#### 4.3.4 Table（目标表）
- 下拉列表: 当前数据库的所有表
- 新建时自动选择当前聚焦的表（MainForm.FocusedTables）

#### 4.3.5 SQL Body
- 支持 NEW.column 和 OLD.column 代码补全
- 自定义 `SynCompletionProposalStatement`: 当 Token 为 NEW 或 OLD 时，列出目标表的所有列名
- 其他场景回退到主窗体的通用补全

#### 4.3.6 解析现有触发器
- 使用正则表达式解析 CREATE TRIGGER 语句
- 提取: DEFINER / Timing / Event / Table / Body
- 格式: `CREATE [DEFINER=user@host] TRIGGER name timing event ON table FOR EACH ROW body`

#### 4.3.7 保存逻辑
- 无 ALTER TRIGGER 支持，采用 DROP + CREATE 策略
- 保存前备份旧 CREATE CODE
- 若新 CREATE 失败，自动恢复旧触发器
- 风险提示: 若恢复也失败，触发器丢失

### 4.4 事件调度器编辑器 (TfrmEventEditor)

#### 4.4.1 名称与 Definer
- 同其他编辑器

#### 4.4.2 调度模式
**Once（一次性）**:
- 日期选择器 `dateOnce` + 时间选择器 `timeOnce`
- 生成 `AT 'datetime'`

**Every（周期性）**:
- 数量 `editEveryQuantity` + UpDown `udEveryQuantity`
- 间隔单位 `comboEveryInterval`: YEAR / QUARTER / MONTH / DAY / HOUR / MINUTE / WEEK / SECOND / YEAR_MONTH / DAY_HOUR / DAY_MINUTE / DAY_SECOND / HOUR_MINUTE / HOUR_MINUTE / HOUR_SECOND / MINUTE_SECOND
- 含下划线的复合单位（如 DAY_HOUR）禁用 UpDown，需手动输入格式如 `1-2`
- 可选 STARTS: 日期+时间
- 可选 ENDS: 日期+时间

#### 4.4.3 过期处理
- `chkDropAfterExpiration`: 默认选中
- 选中: `ON COMPLETION NOT PRESERVE`
- 未选中: `ON COMPLETION PRESERVE`

#### 4.4.4 状态
- **grpState** (TRadioGroup): Enable / Disable / Disable on slave

#### 4.4.5 SQL 预览
- 双标签: CREATE code + ALTER code
- 按需生成: 切换到对应标签时才生成（缓存有效性标志 `CreateCodeValid/AlterCodeValid`）
- 编辑模式下 ALTER code 标签可见

#### 4.4.6 CREATE/ALTER 语句生成
```sql
CREATE|ALTER [DEFINER=...] EVENT name
  ON SCHEDULE
    AT '2024-01-01 00:00:00'           -- Once
    EVERY 1 DAY STARTS '...' ENDS '...' -- Every
  ON COMPLETION [NOT] PRESERVE
  [RENAME TO new_name]                  -- 仅 ALTER 且名称变更时
  ENABLE|DISABLE|DISABLE ON SLAVE
  COMMENT 'comment'
  DO BEGIN ... END
```

### 4.5 创建数据库 (TCreateDatabaseForm)

#### 4.5.1 数据库名称
- `editDBName` (TEdit)
- 新建模式: 空
- 编辑模式 (modifyDB): 显示当前数据库名

#### 4.5.2 排序规则
- `comboCollation` (TComboBox)
- 从 CollationTable 加载所有可用排序规则
- 优先级: 当前数据库排序 > 上次使用 > 服务器默认 > utf8mb4_unicode_ci > 第一项
- 显示服务器默认排序标签

#### 4.5.3 SQL 预览
- 实时生成 `CREATE DATABASE name /*!40100 COLLATE collation */`
- 使用 MySQL 条件注释语法

#### 4.5.4 新建数据库
- 执行 CREATE DATABASE
- 保存排序规则到注册表 `asCreateDbCollation`
- 刷新对象树

#### 4.5.5 编辑/重命名数据库
- 仅改排序: `ALTER DATABASE name COLLATE collation`
- 重命名: 复杂流程:
  1. 检查旧库是否有存储过程（不支持移动）
  2. 检查新库是否有同名对象冲突
  3. 新库不存在则创建
  4. `RENAME TABLE old_db.table TO new_db.table` 批量迁移
  5. 确认旧库为空后 `DROP DATABASE`
  6. 更新注册表中的数据库名记录

### 4.6 数据库对象选择器 (TfrmSelectDBObject)

#### 4.6.1 树形浏览
- `TreeDBO` (TVirtualStringTree)
- 复用 MainForm.DBtree 的树结构和图标
- 支持多选 (toMultiSelect)
- 仅显示当前连接的节点，其他连接节点禁用

#### 4.6.2 自定义数据库
- `editDb` (TEdit): 手动输入数据库名，支持通配符
- 树选择和文本输入互斥:
  - 编辑文本框时: 树变灰，OK按钮基于文本启用
  - 选择树节点时: 文本框变灰，自动填充数据库名

#### 4.6.3 节点选择逻辑
- 根节点(服务器): 数据库名设为 `%`（通配所有库）
- 数据库节点: 数据库名，支持通配符转义
- 表/列节点: 自动提取所属数据库名
- 返回 `TDBObjectList`

## 5. 业务规则与约束

### 5.1 方言兼容性
| 功能 | MySQL | MariaDB | PostgreSQL | SQLite |
|------|-------|---------|------------|--------|
| 视图 Algorithm | ✓ | ✓ | ✗ | ✗ |
| 视图 Definer | ✓ | ✓ | ✗ | ✗ |
| 视图 SQL Security | ✓ | ✓ | ✗ | ✗ |
| 视图 Check Option | ✓ | ✓ | ✗ | ✗ |
| 触发器 INSTEAD OF | ✗ | ✗ | ✗ | ✓ |
| 事件调度器 | ✓ | ✓ | ✗ | ✗ |
| 存储过程 Definer | ✓ | ✓ | ✗ | ✗ |

### 5.2 保存策略差异
| 对象 | 策略 | 原因 |
|------|------|------|
| 视图 | CREATE/ALTER VIEW | 原生支持 ALTER |
| 存储过程/函数 | DROP + CREATE (via temp) | MySQL ALTER PROCEDURE 不支持改参数 |
| 触发器 | DROP + CREATE (with backup) | 无 ALTER TRIGGER |
| 事件 | CREATE/ALTER EVENT | 原生支持 ALTER |

### 5.3 权限检查
- 视图: 无 SHOW CREATE VIEW 权限时禁用编辑器
- 存储过程: 无 SHOW CREATE FUNCTION/PROCEDURE 权限时禁用编辑器
- 触发器: 解析 CREATE CODE 失败时 Body 为空
- Definer 下拉: 从 `mysql.user` 查询，需要相应权限

### 5.4 通用约束
- 所有编辑器的 Name 字段 MaxLength = NAME_LEN
- 保存前检查 Name 非空
- 修改标志 `Modified` 控制 Save/Discard 按钮状态
- 保存失败时显示错误对话框，保持编辑器打开

## 7. 边界情况

### 7.1 视图
- 视图重命名与 ALTER 同时发生时，生成两条语句（ALTER + RENAME TABLE）
- 视图 Body 为空（无权限）时整个编辑器禁用，红色提示

### 7.2 存储过程/函数
- 临时例程名冲突时自动递增序号
- 类型切换（Procedure↔Function）时 FAlterRoutineType 更新
- 函数参数方向强制为 IN，Context 列灰色显示
- 参数类型编辑时自动大写关键字（如 `int` → `INT`）

### 7.3 触发器
- 保存失败时尝试恢复旧触发器代码
- 恢复也失败则触发器丢失，需用户手动修复
- SQLite 的 INSTEAD OF 选项仅 SQLite 连接时显示
- 新建触发器时自动选中当前正在查看的表

### 7.4 事件调度器
- 复合间隔单位（DAY_HOUR 等）需输入 `1-2` 格式，UpDown 禁用
- CREATE code 和 ALTER code 缓存按需刷新
- ALTER code 标签仅编辑模式可见

### 7.5 创建数据库
- 重命名数据库时若旧库包含存储过程，拒绝操作
- 目标库存在同名对象时拒绝操作
- 目标库已存在但无冲突时提示确认迁移
- 迁移完成后检查旧库是否为空，为空才 DROP

### 7.6 对象选择器
- 非当前连接的服务器节点禁用
- 根节点选中时数据库名设为 `%`（全局权限）
- 窗口大小持久化到注册表
